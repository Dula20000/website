        How it works

        Link — visual pairing

        The sender's screen shows a code containing a one-time address on this server. The receiver scans it with any camera app, which opens this page and joins automatically. The two devices then open a direct connection and the file moves between them at network speed.

        The server only introduces the two devices. File contents never pass through it.

        Beam — the code is the file

        The file is split into blocks and painted on screen as a fast stream of codes. The receiving camera reads them back and rebuilds the file.

        Frames are fountain-coded: each one is a combination of several blocks rather than one numbered piece. The receiver can start watching late, look away, drop half the frames, and still finish — it just needs slightly more frames than the file has blocks. Nothing needs resending, which is why there is no back-channel and no pairing at all.

        Every transfer is checked with a CRC-32 before it is saved.

        Formats

        Both paths move raw bytes and carry the original filename and media type, so anything works — photos, video, PDFs, archives, code, 3D models, databases. Nothing is re-encoded.
